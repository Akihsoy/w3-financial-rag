# 家电行业 2026 半年报问答库（W3 作业 · 方向 A）

把 15 家 A 股家电上市公司的 2026 年半年度报告全文（2588 页、310 万字）做成一个
**能提问、答案带出处**的知识库：切块 → 向量 + BM25 双索引 → 混合检索 → 大模型按材料作答。

> 一句话结论（本作业最终答的那句）见文末「结论」一节。

## 这个库里有什么

| 项 | 数 |
|---|---|
| 公司 | 15 家（美的/格力/海尔智家/海信家电/TCL智家/长虹美菱/苏泊尔/九阳/老板电器/华帝/小熊电器/新宝/石头科技/科沃斯/飞科） |
| 报告期 | 2026 年半年度报告（2026-08 披露） |
| 页数 / 字数 | 2,588 页 / 约 310 万字 |
| 还原的表格 | 3,852 张（按行列还原成 `科目 \| 本期 \| 上期` 的行文本） |
| 文本块 | 6,704 块（正文 3,244 + 表格 3,460），800 字一块、重叠 120 字 |
| 向量 | Qwen3-Embedding-0.6B，1024 维，本机计算 |
| 检索 | 向量（余弦）+ BM25（jieba 分词）双路，RRF 合并 |
| 回答 | DeepSeek（`deepseek-v4-flash`），只依据召回材料、逐句带 [编号] |

## 怎么跑起来

```bash
pip install -r requirements.txt

# 1) 下载财报（约 31 MB；key 与网络都不需要）
python scripts/01_download.py

# 2) 提取文字与表格（约 8 分钟，2588 页）
python scripts/02_extract.py

# 3) 切块（秒级）
python scripts/03_chunk.py

# 4) 编码成向量（有 N 卡约 2 分钟；纯 CPU 会非常慢，见「踩坑」）
python scripts/04_embed.py

# 5) 建 BM25 索引（约 20 秒）
python scripts/05_index_bm25.py

# 6) 命令行问一句试试
python scripts/06_ask.py --q "美的集团上半年货币资金是多少"

# 7) 起网页版
python scripts/07_serve.py        # 打开 http://127.0.0.1:8765
```

**密钥怎么放**：复制 `.env.example` 成 `.env`，填 `DEEPSEEK_API_KEY`。
`.env` 已经在 `.gitignore` 里，**密钥不会进仓库**；代码里也从不把 key 下发到浏览器。

## 四种检索模式（对应课件实验一到实验三）

页面上可以切换，用来复现课件里的对照实验：

| 模式 | 做什么 | 课件里对应的结论 |
|---|---|---|
| `vector` | 只用向量余弦 | 语义相近秒级召回，但分不清口径、拼不出全景 |
| `bm25` | 只用 jieba + BM25 | 科目名/年份/专有名词最准，口语化提问会被铺垫带偏 |
| `hybrid` | 两路各取 30 块，RRF 合并 | 两条路的漏项不重叠，合并后更稳 |
| `rewrite` | 先用 LLM 把问题压成一句检索式再混合 | 长口语问题洗掉铺垫；短而正式的问题几乎没变化 |

## 踩坑记录（这几条都真实发生过）

1. **CPU 跑 embedding 模型要命。** 本机（16 核 AMD）实测 Qwen3-Embedding-0.6B 只有
   **0.1 块/秒**，6704 块要十几个小时。换成 CUDA 版 torch（RTX 3060）后约 **60 块/秒**，
   2 分钟算完。教训：先量速度再决定算力，别默认「CPU 也能跑」。
2. **`\s+` 会吃掉换行。** 清洗 PDF 文字时用 `re.sub(r"\s+", " ", t)` 把整张利润表
   串成了一行（单元格之间的换行没了）。只替换空格、别动换行，表格才不会烂。
3. **思考模式很贵。** DeepSeek 默认带推理过程，简单任务（改写查询）加上
   `reasoning_effort="none"` 后 token 数从 30+ 降到 1，响应快一倍。
   课件里踩过同一个坑（输出 token 81% 是推理）。
4. **表头必须跟着表格块走。** 表格切开以后，如果表名只留在前面的块里，
   模型拿到一堆数字分不清是合并口径还是母公司口径——所以每块表格都重复表头两行。
5. **单位不统一是真实陷阱。** 美的的利润表用**千元**，格力、海尔用**元**。
   直接比「销售费用谁最高」很容易翻车（详见 `results/逐题记录.md` 第 7 题）。

## 结论

> 同一批财报里，**要点状事实**（某家公司某个科目的数字、某项政策怎么写）适合建库——
> 答案落在两三块里，检索加强制引用就能答对；**要跨公司横向比、要口径统一的判断**
> 也适合建库、但必须靠检索侧做手脚（同指标多公司分别召回、单位口径归一），
> 靠一次性向量召回拼不出全景；**只有"回答的格式和口径"这类每次都要重复的东西**
> （比如固定按"结论-依据-出处"三段式答、固定把千元换算成亿元）才值得微调，
> 因为那是习惯、不是知识——知识会更新，习惯才进权重。
